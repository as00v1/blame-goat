# BlameGoat · LOL背锅侠

LOL 赛后战报工具。每局结束后从本机客户端读取战绩，整理成**去关联化**的客观数据，交给 DeepSeek 判定谁是**大腿 / 背锅侠 / 不粘锅 / 混子**，生成战报与语音播报。

> ⚠️ **形态说明（v1.1.1 起）**：**单文件 exe（Node SEA）已下线**，只剩桌面客户端（`npm run pack:desktop`）。
> 所以本文里出现的 `npm run pack` 全是**历史记录**，不是能跑的命令 —— 构建脚本 `tools/build-exe.mjs`
> 已随之下线删除；`src/env.mjs` 里的 SEA 分支留着只为兼容，正常打包路径不会再走到它。

- **目标模式**：海克斯大乱斗（嚎哭深渊，**mapId = 12 / queueId = 2400**，真机实测）
- **当前状态**：**可运行版本 + 真机全链路已跑通 + 已能打成单文件 exe**。LCU 对接 / 数据整理 / 判定链路 / 界面 / 自动监视 / 召唤师查询全部接通，**运行时零 npm 依赖**；已在真实对局（29:10 / 191 条事件 / 10 名玩家）上端到端验证。界面**首页即当前账号战绩列表**；**「看」与「判」分离** —— 点行只看详情（不花 token），判定要显式点「开始分析」；判定结果本地缓存，**同一局不重复判定**；列表行直接带输出 / 承伤；评分表支持**按阵营 / 结论 / 定位三种分类**；提示词已升 **v3.0**（多维分析 + 更长报告）；`npm run pack` 出 **84MB 单文件 exe**，目标机器不用装 Node
- **合规边界**：纯本地只读，不做内存读取 / 注入 / 改包；不做自动接受、自动点赞、模拟键鼠

## 一、怎么跑

### 启动

双击 **`start.bat`** —— 起本地服务并自动打开浏览器界面。

```bat
start.bat                  :: 默认端口 7710，自动开浏览器
start.bat --no-open        :: 不自动开浏览器
set PORT=7711 && start.bat :: 换端口
```

服务只监听 `127.0.0.1`，不对局域网暴露。`Ctrl+C` 退出。

### 环境自检

双击 **`check.bat`**，或直接跑：

```bash
node tools/lcu-selftest.mjs       # 客户端：装没装 / 跑没跑 / 能不能应答 / 当前阶段
node tools/check-identifiers.mjs  # 源码：有没有「调用了但没导入」的标识符
node tools/check-perspective.mjs  # 战报：敌我分组有没有塌（我方 0 人或 10 人）
node tools/check-prompt-sync.mjs  # 提示词：web/prompt.js 是不是忘了跟着源文件重新生成
node tools/deepseek-check.mjs     # DeepSeek：网络通不通 / Key 有没有效
```

> `check-identifiers.mjs` 是零依赖版的「未定义变量」检查。
> Node 只在**真正执行到那一行**才抛 `ReferenceError` —— 漏导入的函数平时不报错，
> 等真跑到那条链路（点开某局详情 / 打完一局自动出报）时才整条链路炸。这个脚本在自检阶段就把它拦下来。

### 界面

| 位置 | 元素 | 作用 |
|---|---|---|
| 首页 主体 | **当前账号战绩列表** | 打开即加载；**点任意一行看这一局的详情**（只读，不花 token） |
| 首页 顶部 | **账号下拉** | 切换查看本机哪个账号的战绩。默认 = 当前登录；没登录时 = 最后一次登录的那个 |
| 首页 右上 | **搜索召唤师** | 查本机客户端缓存里**见过的人**，切过去看 TA 的战绩（见下）。结果与「我的战绩」物理隔离 |
| 首页 右上 | 刷新 | 重新读取当前账号战绩 |
| 战报页 顶部 | **开始分析 / 重新判定** | 全站**唯一**会调用模型的按钮 —— 「看」和「判」由它分界 |
| 首页 底部 | 读取上一局战报 | 走真实链路：连接探测 → EOG / 对局记录 → 整理 → 判定 |
| 首页 底部 | 演示一局 | 用**真机抓取的脱敏样例**跑一遍（无客户端也能看真实尺度的效果） |
| 首页 底部 | 探测客户端 | 实时自检并刷新顶部状态 |
| 首页 底部 | 设置 / 提示词 | 次级入口；进独立的**配置页**（见下） |
| ← 返回 | 战报页 / 配置页左上角 | 回上一层；页签之间来回切不入栈 |

页面结构：**首页（当前账号战绩）/ 分析中 / 战报页（战报·播报·历史）/ 配置页（设置·提示词）**。

> **战报页里为什么没有「战绩」页签**：首页已经是完整的战绩列表，战报页再挂一个页签，
> 点进去看到的和首页一模一样 —— 纯重复展示，还多一次入口要选。已去掉，
> 连带去掉的还有首页那个「完整战绩页」链接（它当初的作用就是跳到那个页签）。

> **首页为什么改成了战绩列表**：原来首页是一个大的「等待对局」雷达动画，进来什么都没有，
> 必须先点一下才看得到东西。现在打开就把当前登录账号的战绩铺出来 —— 打完一局想看谁背锅，
> 直接点那一行。等待对局的状态（客户端 / 端口 / 阶段 / 模式）压缩成顶上的一行，不再占半屏。
> 首页与战报页的「战绩」页签共用同一份渲染（同一套 `.mh-row`），不是两套实现。

> **配置为什么单独成页**：设置与提示词是全局的，跟具体哪一局无关。挂在战报页的页签里，
> 每翻一局战报上面都顶着两个与本局无关的入口。所以它们从战报页拆出去、单独成页，只从主页进。
> 两套页签各管各的容器（`#tabs → #page-report`、`#cfgTabs → #page-config`），互不串扰。

#### 「看」与「判」是两件事 ★

点开列表一行**不再自动调模型**。默认只走 `/api/match-detail`：拉这一局的客观数据
（10 个人的英雄 / KDA / 海克斯 / 出装 / 时间轴）铺成战报页，**不花一分钱**。

要不要花钱由页顶那条 `analyze-bar` 决定 —— 它是**全站唯一**会调用 DeepSeek 的入口：

| 状态 | 提示条 | 按钮 |
|---|---|---|
| 这一局没判定过 | 「这一局还没判定 —— 上面是原始数据，点右边才会调用 DeepSeek」 | **开始分析** |
| 已判定过（盘里有战报） | 判定来源 + 消耗 tokens + 「重新判定会再调用一次模型」 | **重新判定** |

- 未判定态下，评分表右边的**评分 / 结论两列留白**，结论写「待分析」，
  点行展开给一句「这一局还没判定」的说明 —— 不假装有结论。
- 「播报稿」页签同理：没有判定结果就不编，直接告诉你先点「开始分析」。
- 后台监视器**默认也只登记不判定**（`data/config.json` 的 `autoAnalyze`，默认 `false`）。
  打完一局只弹一句「已记入战绩，点开可看详情」，要恢复旧的「打完自动出报」，
  去**设置页**把「赛后自动分析」打开。

> **为什么要拆**：自动判定曾经是默认行为，打一局就调一次模型。但大部分时候你点开只是想
> 看看这局谁玩得离谱、带了什么装备 —— 这根本不需要模型。原来的交互把「看数据」和「下结论」
> 绑在一个动作上，等于每次「看一眼」都收一次费。现在拆开了：**想看随时看，想判再点**。

#### 查询召唤师 ★

首页右上角可以直接查别人 —— 但**只能查到本机客户端见过的人**，这是 LCU 的边界，不是实现偷懒：

| 尝试 | 结果 |
|---|---|
| `/lol-summoner/v1/summoners?name=` | 只吃 `gameName#tagLine`；中文名直接 `422 INVALID_EMPTY_REQUEST` |
| `/lol-summoner/v2/summoners?name=` | `400 Unknown argument 'name'`（`puuid` / `puuids` 同样不认） |
| `/lol-summoner/v1/summoners/{puuid}` | `400` —— 这个接口要的是 summonerId，不是 puuid |
| `/lol-chat/v1/friends` | 空数组（本机没加好友） |
| `/lol-match-history/v1/products/lol/{puuid}/matches` | **入参被忽略** —— 拿真账号 puuid 和 4 个随机好友 puuid 去问，回来的都是同一批 gameId |

最后一条是关键：能查到的「别人」= **本机客户端缓存里出现过的人**。所以先立一份**名录**：

- `data/roster.json`，`{ games: { gameId: [ {pid, puuid, name} ] } }` —— 每读一局对局详情，
  就把 10 名参与者攒进去。首次从 `data/account-probe.json` 播种一次（实测 **2980 人 / 395 局**）。
- 搜索走 `/api/summoner/search?q=`，精确命中排最前（查得到多少人，界面上会明说）。
- 选中某人 → `/api/summoner/matches?puuid=` 逐局读详情，结果按 TA 的视角分「我方 / 敌方」。

**数据隔离**（物理上分开放，不是靠 flag 控制）：

| 写哪儿 | 内容 |
|---|---|
| `data/searched/{puuid}.json` | 查询结果缓存，TTL 10 分钟 |
| ❌ 不写 `data/matches.json` | 「我的战绩」索引一个字不动 |
| ❌ 不写 `data/accounts.json` | 账号登记表不因为查了谁就多一个人 |

实测：查 195 局的一个人前后，`matches.json` 从 259883 字节到 259883 字节（逐字节未变），
`accounts.json` 同样未变。查询期间新增的「见过的人」只进名录（那是只读参考表，不属于任何人）。

> **顺手做的一层缓存**：`readMatchDetail` 加了内存缓存（TTL 10 分钟 / 上限 600 局）。
> 实测同一批人重叠对局时：第一个人 5.5s → 第二个人 25ms → 命中缓存 6ms。
>
> ⚠️ 试过给 LCU 调用加 `https.Agent({ keepAlive: true })`，**反而更慢**（16.6s vs 5.5s）——
> LCU 在长连接下响应波动很大，已回退，代码里留了注释警告，别再试。

#### 多账号：一台机器换着登录，数据不混

本机换账号登录很常见。所以每一局、每份战报都记**归属账号（puuid）**，
列表 / 历史 / 已分析计数全部按账号过滤 —— 默认只显示当前登录账号的，看不到别人的。

| 情况 | 默认看谁 |
|---|---|
| 客户端登录着 | 当前登录账号 |
| 客户端没开 | 最后一次登录过的账号 |

顶部下拉可以手动切到本机任何登记过的账号（还能看「全部账号」排查）。
**切换只存在内存里**：关掉再打开还是回到默认 —— 不然上次瞄了一眼别人的号，下次打开就跑到那边去了。

> **归属是怎么认出来的**（`tools/probe-accounts.mjs` + `tools/migrate-accounts.mjs`）：
> 一台机器同时只能登一个账号，所以「登记过的账号 u 出现在某局参与者里」⟹「这局出自 u」。
> 反过来，光看一局里 10 个人认不出谁是「我」（对局详情没有本机标记），
> 所以第二个账号靠**排除法**：扣掉已知账号的局之后，剩下的局里「场场都在」的那个就是它。
> 实测 400 局干净二分：当前账号 200 局，另一个账号覆盖剩余 195/195 = 100%，
> 而好友最高只有 66% —— 好友是做不到场场都在的。

> **战报归属与重判**：重判别人的局**不再被拒**。原来只认「当前登录账号必须在这局里」，
> 换个账号登录之后就再也重判不了老战报（报 `NOT_MY_MATCH`，连模型都不调、更不写盘 ——
> 表现就是「重判了但本地没更新」）。现在按 ①战报已记的主人 → ②索引里的主人 →
> ③当前登录账号在这局里 三级判定，并且**判完仍记在原主人头上**，不会被判走。

#### 界面静态快照

```bash
node tools/render-preview.mjs --page=home              # 首页：账号下拉 + 日期分割
node tools/render-preview.mjs                          # 战报页：已判定态（评分表 + 时间轴 + 「重新判定」）
node tools/render-preview.mjs --state=detail           # 战报页：未判定态（「待分析」+「开始分析」）
node tools/render-preview.mjs --group=label            # 评分表按结论分（另有 --group=role 按定位）
node tools/render-preview.mjs --mode=live              # 盘里现成战报的原样
```

产物落在 `preview/`，是**自包含静态快照**（CSS 内联、无 JS），双击就能看。
图标仍从本地服务实时取，所以要先起服务。

| 模式 | 数据 | 用途 |
|---|---|---|
| `--mode=sample`（默认） | 样例包 `prototype/sample/eog.json`（有 `playerAugment1-6`）+ 落盘战报 `401141430317.json` 的 `result` —— **同一局**，pid 逐一对得上 | 看**新格式界面**的真面貌。**不调模型、不烧 token** |
| `--mode=live` | 直接读盘里那份战报 | 看**当前真实状态** |

| 状态 | 内容 |
|---|---|
| `--state=report`（默认） | 已判定态：有评分结论、按钮是「重新判定」。文件名沿用 `report-preview.{mode}.html` |
| `--state=detail` | 未判定态：只有客观数据、按钮是「开始分析」。另存为 `report-preview.{mode}.detail.html` |

> 渲染器走的是界面自己的真实路径（`BBX.matchDetail` → `applyReport` / `applyDetail`），
> 不是把结果拼出来。**踩过一次坑**：`BBX` 桩里漏了 `matchDetail`，点行抛的 TypeError 被
> `openMatch` 的 catch 吞掉，而评分表在 app.js 启动时就已被内置样例渲染过一遍 ——
> 于是快照看着正常，其实压根没走新链路。现在点行前会**先清空容器**，
> 清完还是空的就直接 `[fatal]` 退出，另外还校验按钮文案与 `--state` 是否一致。

> 为什么不用无头浏览器截图：这台机器 npm 不通装不了，而且页面挂着 SSE 长连接，
> Edge `--headless` 永远等不到 idle，两次都超时。既然 `web/app.js` 是纯 DOM 操作，
> 就用 `ui-smoke.mjs` 同一套 DOM 桩把它真跑一遍，再把渲染出的 `innerHTML` 灌回容器 ——
> 出来的就是浏览器里那份 DOM。**验的是「DOM 结构与数据」，不验「像素」。**

### 评分表 ★

战报页的主视图：**同样 10 个人，三种分类看法**，每人一行，行内六列 ——

```
玩家 / 英雄            K/D/A      海克斯           出装                评分   结论
[头像] 普朗克  19/16/25   [4 格符文图标]   [6 格装备图标]        58   普通
       路人己 · 战士                                              ▬▬▬
```

**分类切换**（评分表上方的分段钮，纯前端重排，不碰数据、不调接口）：

| 分类 | 回答的问题 | 分组 |
|---|---|---|
| **按阵营**（默认） | 谁是我的队友 | 我方 / 敌方 |
| **按结论** | 谁该背锅 | 大腿 / 背锅侠 / 混子 / 不粘锅 / 普通 |
| **按定位** | 这阵容缺了什么 | 坦克 / 战士 / 刺客 / 法师 / 射手 / 辅助 |

- **阵营是不可替代的那一维** —— 它回答的是「谁是我的队友」，所以做默认；
  结论 / 定位是补充视角，用来换角度看同一批数据。
- 组内一律**按分数降序**；没判定的局分数缺失，排序退化成原序（不影响任何显示）。
- 组标题右侧带**摘要**：阵营视图给标签分布（「大腿×2 · 混子×1」），
  结论 / 定位视图给阵营构成（「我方 2 · 敌方 1」）——换了个排法也不至于认不出谁是哪边的。
- 没判定时点「按结论」会**自动退回按定位** —— 10 个人全挤进「待分析」一组，没有信息量。
- 评分那一格下面加了**评分条**（宽 46px，随分数上色）：数字给人算，条给人看，十行扫下来谁高谁低一眼分明。

- **左半是客观数据**（K/D/A、海克斯、出装），**右半是判定结果**（评分、头衔）——
  「他带了什么」和「我们怎么判」摆在同一行，才对照得起来。
- 列宽由 grid 定死：10 行之间必须能竖着比，某个人多一件装备不该让整列跑偏。
- 符文格按稀有度描边（银 / 金 / 棱彩 / 事件），低饱和，只做区分不抢戏。
- **点行展开**：参团率 / 每分钟伤害 / 承伤 / 经济，加上判定理由与逐条证据。默认收起，不占地方。
- 图标走 LCU 资源代理；**取不到就退到首字占位**（「暴」= 暴击飞弹，「莫」= 莫雷洛秘典），
  名字始终进 `title`，鼠标停一下就能看到全称。离线演示整列都是首字，也照样看得出带了什么。

> **出装会滤掉守卫与饰品**（2052 控制守卫、3340 监视守卫等）。它们占着物品栏格子，
> 但跟「出装」没关系 —— 不滤的话每人第 7 格永远是个眼石，反而看不清真正的六件成装。
> 新装备总是先出现在客户端、晚一步才有中文名，所以查不到名字的**保留原始 id**（显示成「装备1234」），不丢格子。

战报页的**时间轴是列表**：一行一个时间点，三列 = 时间 / 类型 / 详情（击杀类带强调色标签，其余中性灰）。
真机一局 190+ 条事件，靠列表内部滚动兜住（`max-height: 460px`），不把整页撑长。

时间轴是全篇**唯一把 10 个人混排**的地方（同一行可能「我方杀敌方」也可能反过来），所以名字按阵营着色：
**我方蓝 `#6094b9` / 敌方红 `#e76463`**，昵称与英雄名同色。攻方、阵亡方、助攻名单共用这一套，
一行之内谁是自己人一眼分清。标题右侧带颜色图例。

> **配色来自 LOL 官方色**：蓝取官方品牌蓝 `#548CB4`（PMS 7454 C，官方色板里有 PMS 编号的那支），

### 战绩列表 ★

**首页打开即是这份列表**。每局一行九格：
对局时间 / 模式 / 英雄 / KDA / **输出** / **承伤** / 胜负 / 是否已分析 / 操作。
**点某一行 = 看这一局的详情**（`/api/match-detail`，只读不花钱）；要判定去战报页顶部点「开始分析」。
已判定过的行，状态格会写「已判定」，点开直接是盘里那份战报。

**「输出 / 承伤」两格**（v2.5 加的）主行是绝对值（`55.7k`），副行是每分钟速率
（`2276/分`）—— 对局时长从 14 分钟到 29 分钟都有，绝对值之间没法直接比。
鼠标悬停给完整数字，外加治疗 / 金币 / 补兵与这一局的判定结论。

> **数据从哪来**：LCU 的 `/lol-match-history/v1/products/lol/current-summoner/matches`
> 实测**每局只回「我」这一名参与者，但那一名带着全套 stats** —— 所以最近约 200 局
> 一次就拿到，不必逐局读详情。更老的条目（超出客户端窗口、或属于另一个账号）
> 由 `listMatches` 的补录步骤按**条目自己的归属账号**从对局详情补 ——
> 早先这一步只补「没有英雄」的条目，现在 `!hasMe || damageDealt == null` 都补。

列表高度是**自适应**的：`.home-list` 用 `flex: 1 1 auto` 吃掉「顶部标题栏 + 汇总行」以下的
全部剩余高度，`min-height: 180px` 兜底矮窗口，滚动条长在列表内部。早先是 `max-height: 320px`
钉死的 —— 屏幕再大也只给这么点，下半屏白白空着。

**同一局不会重复判定** —— 这是硬规则，四条入口共用：

| 入口 | 走的路 | 已有战报时 |
|---|---|---|
| 首页点行 | `/api/match-detail` | 直接读盘回放（**不调模型**） |
| 战报页「开始分析」 | `/api/analyze-match` | 直接读盘，不重复判定 |
| 读取上一局战报 | `/api/analyze`（EOG 优先） | 直接读盘 |
| 打完自动出报（需在设置里打开） | 监视器 → `analyzeWithConn` | 直接读盘 |
| 显式「重判 / 重新生成」 | 同上，带 `force` | **重新判定** |

判定结果落盘在 `data/reports/{gameId}.json`，只要文件在就直接读回来（响应带 `fromCache: true`），
不调模型、也不重复写盘。对局数据是不可变的，重跑一次只是白烧一次 token（约 ¥0.004 也是钱）。

> **这里补过一次漏**：早先只有「按 gameId 分析」那条路做了缓存，`EOG / 读取上一局 / 自动出报`
> 那条路每次都会重新调模型 —— 同一个界面上的两个按钮，一个省钱一个烧钱。现在两条路都先查盘。

> **又补过一次漏（界面侧，2026-10-10）**：缓存做对了，但**前端不等响应就先亮「正在生成战报」页**。
> 点一条已分析过的记录，服务端 14ms 就把战报读回来了，界面却先演满约 2 秒进度动画
> —— `animateSteps()` 第一行就是 `show('analyzing')`，且 4×420ms + 320ms 是**固定时长**
> （`minMs` 只是下限，根本拦不住）。
>
> 现在改成**请求先行**：已分析过的记录先给 900ms 窗口等读盘返回，
> **命中 → 一个页面都不切**（只把被点的那行压暗、状态格换成「读取中…」），超时才亮进度页。
> 实测进战报页耗时 **≈2000ms → 16ms**。`读取上一局` 同一处理（按钮自己进忙碌态兜住那 900ms）；
> `演示一局` 原来更糟 —— 先**干等**请求（联机时是真调模型，十几秒黑屏）再补演 1.7 秒假动画，现已改为并行。

数据来自三处合并（同一局按 `gameId` 去重，LCU 来源优先级最高）：

| 来源 | 能给什么 | 局限 |
|---|---|---|
| LCU 对局列表 | 精确到本人的英雄 / KDA / 胜负 / 对局时间 / **输出 / 承伤 / 治疗 / 金币 / 补兵** | 只覆盖客户端本地缓存（实测 100+ 局，随缓存积累变化），再往前没有 |
| `data/reports/*.json` | 已判定过的局（含结论） | 只有阵营，不知道本人玩了谁 |
| `data/matches.json` | 本地累积索引 | 仅本工具见过的局 |

> **「所有战绩」= 客户端缓存 ∪ 本工具攒下的索引**：
> `/products/lol/current-summoner/matches` 一次返回本地缓存的全部历史
> （实测 `gameCount` 从 101 长到 200+，随客户端缓存积累变化；`begIndex/endIndex` 传多少结果都一样，
> 也没有分页 / refresh 入口。**每局只回「我」这一名参与者，但那一名带全套 stats** —— 所以列表行
> 不必逐局读详情就能显示输出 / 承伤），
> 客户端缓存被清空也不会丢 —— 因为每见到一局就记一笔（`data/matches.json`）。
> 对局**详情**同样任意 `gameId` 都能查（老对局也能补全英雄）。

服务启动后**自动监视**客户端（每 5s 一次），两条路谁先发现算谁：

1. 阶段进入结束态（`WaitingForStats` / `PreEndOfGame` / `EndOfGame` 任一）—— 快，但 EOG 接口窗口常只有几秒
2. 每 30s 查一次「最近一局 gameId」，一变就登记 —— 慢一点，但对局记录打完永久可查，是漏网的兜底

> **默认只登记、不判定**（`autoAnalyze: false`）。发现新对局时广播一条 `newgame` 事件，
> 界面弹「检测到新对局 · 已记入战绩，点开可看详情」并静默刷新列表 —— **不调模型**。
> 想要旧的「打完自动出报」，去设置页打开「赛后自动分析」。

> 而且**拿不到 EOG 也能判定**：自动退到 `/lol-match-history/v1/games/{gameId}`，字段比 EOG 更全（自带 participantId / queueId / mapId），结果等价。
> 另有 `tools/watch-eog.mjs` 蹲守器，把原始响应全部落盘，用于核对字段。

### 打包成 exe（单文件，目标机器不用装 Node）　—— **已下线，仅供沿革参考**

> ⚠️ **这一节已下线**：单文件 exe 形态 v1.1.1 起不再维护，`npm run pack` 这条命令
> 在 `package.json` 里**已经不存在**，`tools/build-exe.mjs` 也随之下线删除。
> 现在的打包只有桌面客户端，见第九节（`npm run pack:desktop` / `npm run pack:update`）。

```bash
npm install --ignore-scripts --registry=https://registry.npmmirror.com   # 只装构建工具，一次性
npm run pack                                                             # → dist/LOL背锅侠.exe（已下线）
```

**为什么是 Node SEA 而不是 Electron**：本工具本体零依赖，界面就是浏览器里的一个页面。
套 Electron 等于为了个外壳塞进 100MB+ 运行时、还要能用的 npm 源；
SEA 直接拿官方 `node.exe` 当宿主，**目标机器不用装 Node、不用装任何东西**。

exe 约 **84MB**（其中 ~83MB 是 Node 运行时本身，我们的代码 + 全部界面资源只有 800KB 左右）。

打包要顺着 SEA 的性子来，三处对应改动都已落在仓库里：

| 约束 | 落点 |
|---|---|
| SEA 入口必须是 CommonJS | `tools/build-exe.mjs` 先用 esbuild 把整个 ESM 项目合成一个 `.cjs` |
| exe 里没有「仓库目录」 | `src/env.mjs` 用 `process.execPath` 定根目录（开发态仍按文件位置算） |
| 界面文件不在磁盘上 | 整个 `web/` 以 assets 内嵌进 exe，运行时 `sea.getAsset` 读 |

**分发时只给 exe 一个文件**。数据（`data/`）在首次运行时自动创建于 exe 同级，
里面装的是英雄表 / 出装符文表这类**公共查表数据**（打包时以 `seed/` 前缀内嵌，首次启动解出来）；
战报、账号、名录、查询缓存**从来就不在 exe 里** —— 它们跟着用户走，不跟着包走。

> ⚠️ 三条实话：
> 1. exe **没有代码签名**，首次运行 Windows 会拦一下：**「更多信息」→「仍要运行」**。
> 2. exe 是控制台程序，**双击会带一个黑窗**（里面是启动信息与实时日志，`Ctrl+C` 退出）。
> 3. 别放进 `C:\Program Files`。真放进去了也不会崩 —— 数据会自动改落到
>    `%LOCALAPPDATA%\LOL背锅侠\data`，**启动日志会明说数据在哪**。

**双击第二次**不会报错：检测到端口已被占用时，直接把人送到已经在跑的那个界面并退出 ——
这是「客户端」该有的反应，而不是甩一句 `EADDRINUSE`。

### API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/status` | 服务 / AI Key / 监视器状态（含 `ai.autoAnalyze`） |
| GET | `/api/selftest` | LCU 环境自检 |
| GET | `/api/asset?p=…` | 代理 LCU 本地资源（英雄图标等），仅放行 `/lol-game-data/assets/` 前缀 |
| POST | `/api/analyze` | `{source:'live'\|'mock', tone, force}` → 战报；live 会自动在 EOG 与对局记录之间选路；已判定过的直接读盘（响应带 `fromCache`） |
| POST | `/api/analyze-latest` | 强制走「最近一局对局记录」（打完永久可查的那条路）；同样带缓存 |
| GET | `/api/matches?limit=&refresh=&account=` | **战绩列表**（时间倒序）；`refresh=0` 只读本地索引、不碰客户端；`account=` 指定 `puuid` / `all` / `unowned`，不传 = 当前查看的账号 |
| GET | `/api/match-detail?gameId=&perspective=` | **对局详情**：盘里有战报就回放（`hasReport:true`）；没有就拉 LCU 详情 + 时间轴整理（`hasReport:false`，**不含 result、不调模型**）。`perspective=` 决定「我方 / 敌方」按谁的视角分 |
| GET | `/api/roster` | 名录状态：认识多少人 / 攒了多少局 / 是否刚播种 |
| GET | `/api/summoner/search?q=` | 按昵称搜名录（精确命中排最前，返回 puuid / 昵称 / 局数）。**查不到 = 本机没见过** |
| GET | `/api/summoner/matches?puuid=&refresh=1` | 某人的战绩（逐局读详情，带 10min 缓存）。**只写 `data/searched/`，不动「我的战绩」** |
| POST | `/api/analyze-match` | `{gameId, force}` → 分析**指定的某一局**；`force=true` 忽略已落盘战报重判（**别人的局也能重判，仍记在原主人头上**） |
| GET | `/api/accounts` | 本机账号清单（含局数 / 已分析数）+ 当前登录 + 最后一次登录 + 正在看谁 |
| POST | `/api/accounts` | `{key}` 切换查看哪个账号（`puuid` / `all` / `unowned`）；**只存内存，重启回默认** |

## 四、LCU 对接说明（真机实测结论）

实测环境：`G:\WeGameApps\英雄联盟\LeagueClient\`（客户端装在 G 盘，非 C 盘；客户端版本 16.20.824.8524，区服 TENCENT / TJ101）

### 4.1 连接层四个坑

| 坑 | 文档预判 | 实测结论与处理 |
|---|---|---|
| **路径不固定** | `C:\WeGameApps\英雄联盟\...` | 实际在 **G 盘**。改为按盘符 × 候选前缀枚举目录，只要 `<dir>\LeagueClient\lockfile` 存在就认，不猜路径 |
| **GBK 编码** | 需 latin1 读原始字节 + gbk 解码 | **本模块完全不依赖外部命令取路径**，用 `fs.readdir` 由 Node 直接拿 Unicode 目录名，从源头绕开。仅在目录名已被写坏时用 `looksLikeLolDir()` 模糊匹配 `英雄联盟` / `鑻遍泟鑱旂洘` |
| **端口每局都变** | 必须 watch 目录而非文件 | 每次调用都重新读连接信息取最新端口，不做缓存 |
| **lockfile 是空的** ★ | 未预判到 | 国服 WeGame 版**哪怕客户端正在运行，lockfile 也可能是 0 字节**（实测 PID 33076 在跑，文件 size=0）。解法：**日志兜底** —— 回退到 `<clientDir>\*_LeagueClientUx.log` 最新那个的开头命令行，正则取 `--app-port` / `--remoting-auth-token`。日志命令行在第 0 行，只读前 64KB |

补充三条实测细节：

- **lockfile 为空 ≠ 没装客户端**。客户端退出后文件仍在但是 0 字节，必须靠「能否解析出端口」区分「已安装」和「正在运行」。
- **端口活不活只能靠 ping**。日志兜底拿到的可能是**上一次**启动的残留，所以 `selfTest` 一律 `pingClient()` 验证后才认 `running`。连接来源用 `connSource: 'lockfile' | 'log'` 标明。
- **不用 WebSocket**。LCU 的 wss 是自签证书，Node 内置 WebSocket 不支持配置 `rejectUnauthorized`。改用轮询 `gameflow-phase`，零依赖且足够。

### 4.2 数据层——单靠 EOG 是不够的 ★★

这是本项目**最贵的一课**。文档原本假设「读 `/lol-end-of-game/v1/eog-stats-block` 就够了」，真机抓下来发现**四件事全不对**，其中第一条会让整个判定崩掉：

| # | 假设 | 真机实测 | 后果与处理 |
|---|---|---|---|
| 1 | 玩家有 `participantId` | **没有**（只有 summonerId / puuid / summonerName） | `pidOf` Map 的键全是 `undefined`，**十个人塌成同一个 pid**（实测全变成 `p10`，界面十张卡同名）。必须用 `/lol-match-history/v1/games/{gameId}` 的 `participantIdentities[].player.summonerId → participantId` 桥接，见 `src/lcu/participants.mjs` |
| 2 | 顶层有 `queueId` / `mapId` | **都没有**（只有 `queueType: "KIWI"` / `gameMode: "KIWI"`） | 模式判断失效。真实值在 match-detail：**queueId = 2400、mapId = 12**；队名在 `session.gameData.queue.name`（"海克斯大乱斗"） |
| 3 | `championName` 是英雄名 | **是称号**（`championId=41` → `"海洋之灾"`） | 界面显示「海洋之灾」而不是玩家口中的「普朗克」。`resolveChampion()` 改为**优先用 championId 查表**，`championName` 只作兜底；称号保留为副标题 |
| 4 | `events` 里有事件 | **恒为空数组** | 时间轴 0 条。真实事件在 `/lol-match-history/v1/game-timelines/{gameId}` 的 `frames[].events`，且字段名完全不同（见下） |

#### 事件字段名对照（时间轴）

| 含义 | 老假设（mock） | 真机（timeline） |
|---|---|---|
| 时间 | `eventTime`（**秒**） | `timestamp`（**毫秒**） |
| 攻击者 | `killer` | `killerId`（`0` = 小兵 / 防御塔） |
| 受害者 | `victim` | `victimId`（`0` = 无） |
| 助攻 | `assisters` | `assistingParticipantIds` |
| 拆建筑目标 | `turret`（单字符串） | `towerType` + `buildingType` + `laneType` 三个枚举 |
| 类型 | FirstBlood / Ace / GameEnd… | 只有 `CHAMPION_KILL` / `BUILDING_KILL` |

实测一局 191 条事件：`CHAMPION_KILL` 181 条 + `BUILDING_KILL` 10 条，**没有** FirstBlood / Ace 这类类型（首杀、团灭要从数据自己推）。

#### 对局列表：先只给 2 局，其实有 100 局 ★★

| 接口 | 真机行为 |
|---|---|
| `/products/lol/current-summoner/matches` | 客户端**刚启动 / 历史未同步完**时只回 2 局（`gameCount = 2`）；同步完成后同一请求返回 **101 局**。`begIndex/endIndex` 传任意值结果都一样（实测 0-100 / 0-300 / 100-200 / 0-1000 全部返回同样的 101 条），`/refresh` 与 `?gameType=` 等变体全部 404 / 400 |
| `/lol-match-history/v1/games/{gameId}` | **对任意 gameId 都返回数据** —— 随手编一个 `401141430000`，回的是**别人的对局**（10 人里没有当前账号），且响应里的 `gameId` 会把请求值原样回填 |

> ⚠️ **教训**：把「客户端刚启动、历史还没同步完」时的响应当成接口能力，
> 会得出「只给最近 2 局」这种错误结论 —— 本项目就据此白做了一套本地累积机制
> （机制本身有保留价值，但当初的论证是错的）。**缓存类接口要先确认同步完成再下判断。**

第 2 条是个坑：不校验就等于「点了 A 局、分析了 B 局」。所以 `analyzeMatch()` 强制核对
`participantIdentities[].player.puuid` 与当前登录账号，不匹配直接 `NOT_MY_MATCH` 拒绝。

顺带一个反直觉的事实：**gameId 与时间不同序**。实测 `401141622010` 比 `401141591981` 编号更大，
但开局时间早了 20 分钟 —— 不能拿 id 大小当先后顺序排（排序必须用 `gameCreation`）。

#### stats 字段

好消息：`stats` 里**大写下划线和小驼峰两套字段并存**（`CHAMPIONS_KILLED` 和 `kills` 都有），所以按小驼峰读能直接取到值。`normalize.mjs` 两套都兜，以应对版本差异。

### 出装 / 强化符文表（`gamedata.mjs`）

两个 LCU 接口，字段名与语义（2026-10-10 实测，LCU 与 CDN 镜像逐字一致）：

## 五、设计基线（改代码前先读）

### 数据层「四不原则」

1. **不排名** —— 不输出任何「第几名 / 最高 / 最低」
2. **不算均值** —— 不输出队内平均值、中位数等参照系
3. **不做因果关联** —— 不标注事件之间「谁导致谁」
4. **不预设关联窗口** —— 不给「X 秒内算关联」这类判定条件

边界一句话：字段是「描述单个玩家 / 单个事件自身」→ 留；是「描述它们之间关系」→ 删。

### 数据隔离：查别人的数据，不能进我的库

「查询召唤师」会拉一个陌生人的几百局。这些局**不属于本机任何一个账号**，
如果顺手写进 `data/matches.json`，就会污染「我的战绩」—— 列表变长、账号归属乱套、
「已分析 N 局」的计数也不对。所以**靠文件物理隔开，不靠标记位**：

| 数据 | 落哪儿 | 谁在写 |
|---|---|---|
| 我的战绩索引 | `data/matches.json` | 只有「当前登录账号 / 本机登记账号」的局才进 |
| 账号登记表 | `data/accounts.json` | 只在本机真登录过才登记；查询**不新增** |
| 查询结果 | `data/searched/{puuid}.json` | 查询专用，TTL 10 分钟，随时可删 |
| 名录（只读参考） | `data/roster.json` | 攒「见过的人」，天然不属于任何人，查询可以往里加 |

守这条线的是 `ui-smoke.mjs` 里的断言：查完一个人之后，重新拉 `/api/matches` 比对
**总条数必须一模一样**，被覆盖就直接判失败。

### 「我方」是哪边 —— 视角从哪来

战报页按 `players[].isMyTeam` 分成「我方 / 敌方」两组，而这个布尔值全部派生自
`dataset.match.myTeamId`（`isMyTeam = teamId === myTeamId`）。
**myTeamId 一旦是 null，`teamId === null` 恒为 false —— 10 个人会全部落进「敌方」列**，
界面上看着就是「这一局没有敌我区分」。

所以视角是三级兜底，缺一不可：

| 级 | 来源 | 什么时候用得上 |
|---|---|---|
| ① | 调用方显式指定 `myTeamId` | mock / 离线样例 |
| ② | EOG 自带标记（`localPlayer.teamId` / `teams[].isPlayerTeam`） | 真机 EOG —— 最直接 |
| ③ | 从 match-detail 里按**归属账号**反查（`teamOfPuuid`） | 重判别人的局 |

第 ③ 级是必需的：从 match-detail 合成的 EOG（`synthesizeEogFromMatchDetail`）
**既没有 `localPlayer`，teams 里也没有阵营标记**，②拿不到东西；剩下的判据只有
「当前登录账号在不在这局里」—— 而换账号之后重判**别人的老战报**时，当前账号压根不在局里，
于是返回 null。表现就是「点重判后，10 个人全跑到敌方列表里去了」。

两道防线：

1. **生成时** —— `analyzeFromEog` 的视角解析链补上 `?? teamOfPuuid(matchDetail, ownerPuuid)`。
   `analyzeMatch` 早就把 ownerPuuid 算出来了（不然它也不会允许判这一局），拿它反查必然命中。
2. **读盘时** —— `readMatchView` 回放老战报时若发现 `myTeamId == null`，
   顺手按归属账号补正并写回（`healPerspective()`）。**只改视角这一维**：
   `myTeamId` / `myResult` / `teams[].isMyTeam` / `players[].isMyTeam`；
   判定结果（标签 / 分数 / 结论 / 理由）与所有客观数据一个字不动 —— 战报是证据，
   不借着修视角改结论。写回后把文件 mtime 还原，免得「历史」页按时间排序把它顶到最前。

> 守这条线的是 `tools/check-perspective.mjs`：扫一遍 `data/reports/*.json`，
> 只要有一份的「我方」是空集就报错退出（`check.bat` 里也会跑）。
> `ui-smoke.mjs` 的「已判定回放」另加了一条 `敌我:5 v 5` 的形状断言。
>
> 真机上确实踩到了：盘里 10 份战报有 2 份 `myTeamId = null`、我方 0 人，
> 归属都是另一个账号 —— 正是「换账号后重判别人的局」造出来的。

### 最关键的一条分界线

> **规则可以给，关联不能给。**
>
> 「death ≤ 1 判不粘锅」→ 写进提示词（不给模型就没标准）
> 「阵亡后 28 秒丢塔 = 代价」→ 禁止（给了就是替模型解题，这 28 秒得它自己算出来）

### 约束方式

不采用代码层正则 / 关键词黑名单 / 固定话术 —— 那是事后用代码猜模型表达。
全部写在提示词里，事前讲清规则，模型保有表达自由，改规则不必改代码发版。

**保留边界**：结构化校验仍由代码执行（JSON 可解析 / 字段齐全 / 枚举合法 / 分数 0-100 / 人数完整），那是解析必需，不是话术限制。

### 提示词 v3.0（当前版本）

| 变更 | 内容 |
|---|---|
| 评估 → **分析** | 「多维评估要求」升级为「**多维分析要求**」：阵容 / 海克斯 / 出装 / 三者联动，四个角度**既支撑个人标签与分数，也各自在 `teamInsight` 里成一段独立结论**（v2.4 只说「支撑判断」） |
| 报告变长 | `insight` 120 字 → **300-400 字**，强制四层结构（阵容 → 海克斯 → 出装 → 节奏）；个人 `reason` 80 字 → **150 字**且要成链；`evidence` 2 条 → **3 条** |
| 团队结论拆三条 | `teamInsight` 由 1 条拆成 **3 条**：`compositionNote`（阵容）/ `augmentNote`（海克斯）/ `itemNote`（出装），各 150 字以内、各写各的 |
| 输出上限 | `REQUEST_CONFIG.max_tokens` 2600 → **4000**，`timeoutMs` 30s → **60s**（输出量翻倍，2600 会**截断 JSON** → 校验失败 → 兜底，白烧一次调用还看不到长文） |
| 硬性约束第 10 条改写 | 由「阵容结论只进 `teamInsight`」改为「**阵容与海克斯只进团队层**」—— 阵容 / 符文是系统随机分配，不压个人分；出装里属**可控决策**的部分（钱花了但装备不解决问题）可以在个人 reason 里说 |

> **v2.4 那批里最要紧的第 8 条仍然在**：大乱斗的随机英雄、随机符文、经济制约都含玩家控制不了的成分，
> 不显式分开「可控的决策失误」与「不可控的随机结果」，模型很容易把随机阵容算成某个人的锅。
> 另外 `teamInsight` 三个字段缺失**都不判为校验失败**，界面按「有就显示、没有连壳子一起收掉」处理 ——
> 为一个可选文本字段把整局打回本地兜底，等于白烧一次调用。

### 隐私与密钥

- 真实昵称**不出本机**：发给模型前深度替换为 `p1`-`p10`。
- **战报文件里只留 pid**（`names` 字段落盘时剔除）—— 战报是要能拿出去给人看的，永远不含真名。
- 真名另存本机 `data/names.json`（`gameId → { p1: 昵称 }`），界面读盘时再还原，所以**自己能看见名字、分享出去也安全**。
  ⚠️ 「分享出去安全」指的是**战报文件本身**（`data/reports/*.json`）。`data/` 这个目录不能整体外发 ——
  它还有 `names.json` / `roster.json` / `searched/*.json` / `account-probe.json`，全是他人真名与 puuid。
- 老战报没记昵称的，读盘时借客户端 `matchDetail` 重建一次（同一套 pid 分配，逐个对得上），之后走缓存。
- 模型返回的文案里写的是 `p1`/`p10`，展示前会还原成昵称 —— 但**只动文本字段**，
  `result.players[].pid` 必须原样保留，它是前端和 `dataset.players[].pid` 对齐的键。
- API Key 优先取环境变量 `DEEPSEEK_API_KEY`（优先级最高），其次 `data/config.json`；两者都没有就走本地兜底判定，功能不中断。

### 兜底判定的尺度标定 ★

本地兜底（没有 API Key 时走的那条路）**必须按大乱斗的真实尺度标定**，否则整条降级链路等于失效。

真机一局 29 分钟的数据分布：

| 维度 | 实测区间 |
|---|---|
| 参团率 | 0.51 – 0.87 |
| 死亡 | 12 – 22 |
| 伤害 / 分钟 | 1100 – 5900 |

早先按**峡谷尺度**写的公式（伤害 ÷ 120、死亡项 `20 - 死亡 × 1.8`）在这局上**两项同时饱和**：伤害项两人就顶格、死亡项全员归零（死亡 ≥ 12 时该项恒为 0），十个人全挤在 42–80 之间 → **一个标签都判不出来，全员「普通」**。

修正后的三处改动：

1. 伤害锚点 `÷120 → ÷250`，死亡锚点改成「从 12 次起罚」，两个维度恢复区分度
2. 大腿 / 战犯改为**相对判定**（全场最高分 / 败方最低分）—— 大乱斗一局 10–30 分钟跨度太大，绝对分数线不可移植。
   判定层允许比较玩家：**四不原则约束的是数据层（不给模型参照系），不是判断层**（模型本来就要判谁是大腿谁该背锅）
3. 标签阈值参数按真机校准：`teflon_death_max` 1 → 4、`freeloader_death_min` 8 → 18
   （原值是峡谷尺度，在大乱斗里一个都触发不了，等于把这两个标签写死了）

> 注意：这样调完之后，一局里**未必**五个标签都出现。实测这局 29 分钟、全员死亡 12+ 次，就确实没有「不粘锅」—— 这是真实结果，不是 bug。想要更丰富的判定，配一个 DeepSeek Key 走模型。

## 九、桌面客户端（Electron 外壳，2026-10-10）

需求原话：**「exe 不止是启动服务，页面也要嵌在客户端中」** ——
原来的单文件 exe 起完服务是用系统浏览器打开页面的，那不算客户端。

于是路线从「SEA 单文件」扩成两条并存，各自解决不同问题
（**后来又收成一条**：v1.1.1 起单文件形态下线，`npm run pack` 这条命令已不存在）：

| 命令 | 产物 | 体积 | 界面 | 定位 |
|---|---|---|---|---|
| ~~`npm run pack`~~ | `dist/LOL背锅侠.exe` | 84MB | 系统浏览器 | **已下线**（构建脚本已删除，见文首说明） |
| `npm run pack:desktop` | `dist/LOL背锅侠/` + zip | 322MB / 139MB | **自家窗口** | 日常使用 |
| `npm run pack:update` | 升级包 zip | ~0.3MB | — | 日常改动只发这一个 |
| `npm run app` | 无产物，直接跑 | — | 自家窗口 | 开发态，改完源码即生效 |

### 结构

```
desktop/main.cjs      Electron 主进程：拉起服务 → 开窗 → 收尾（全项目唯一的 CJS）
server/server.mjs     同一个 HTTP 服务，改成「可被 import 的服务」+「可命令行直跑」
src/env.mjs           形态判断从两态扩到三态（开发 / SEA / Electron 客户端）
tools/build-desktop.mjs   打包：下 Electron 官方 zip → 组装 → 改名换图标 → 截图自检
tools/make-icon.mjs       纯 Node 手写 PNG+ICO 生成图标（不引图像库）
```

`server.mjs` 抽出 `export function startServer({port, open, quiet})` 返回实际地址：
桌面端 import 它、端口给 **0**（系统自己挑空闲的，永远不会和命令行那份服务抢 7710）；
命令行与 SEA exe 仍走文件末尾的 `isDirectRun()` 分支自动启动，行为一字未变。

### 八个真机踩出来的坑（都不是 Electron 的错，但都能耗掉一下午）

1. **`fs.cpSync` 会静默失败。** 目标路径含非 ASCII（产物就叫 `dist/LOL背锅侠/`）时，
   某些环境下它**不抛错、不复制、直接返回**，脚本照常往下跑 —— 最后打出一个只有
   `package.json` 的空客户端，Electron 找不到 main 就默默退出，连日志都不留。
   → 改手写 `copyTree()`（mkdir/readdir/copyFile），实测稳。

2. **`ELECTRON_RUN_AS_NODE=1` 会让 Electron 变成纯 Node。** 这时它**不加载 resources/app**，
   挂在 stdin 上等输入。现象极具误导性：进程活着、不崩不退、没有窗口、没有任何日志。
   → 拉起 Electron 前必须 **delete** 这个变量（设成空串无效，Electron 只看键在不在）。

3. **未知的 `--shot=xxx` 会被转给 Chromium，然后 `bad option` 直接退出（码 9）。**
   所以客户端自检用的截图参数走**环境变量** `BBX_SHOT`，不走命令行开关。

4. **「解压完再删不要的语言包」在 Windows 上做不干净。** 刚解开的上千个文件会被 Defender
   实时扫描摸一遍，期间删除 EPERM —— 第一版因此漏下 27 个语言包（3.5MB）留在包里，
   而且异常被 catch 吞了，报告上写着「已精简」。→ 改成**解压时就 `--exclude`**，不让它们落盘。

5. **234MB 的 exe 改名后立刻用 rcedit 换图标会 "Unable to commit changes"**（Defender 正扫它）。
   → 重试 2 次、每次间隔 1.2s；三次都失败也只是文件图标是默认的，不影响功能。

6. **环境的批量删除保护会让打包在最后一步突然中断。** `makeZip` 里顺手 `rmSync` 一下旧 zip，
   看着无害，但在「一个回合删太多文件」的保护下会直接抛错打断整条链。
   → 能覆盖就别删（bsdtar 本就覆盖同名文件）。同一个原因还引出两个设计决定：
   构建全程在 `.build/`（纯 ASCII）里做、最后改名归位；旧产物用 **改名挪走**（O(1)）而不是原地删 ——
   第一版「删不掉就改名」的兜底，每打一次包就在 `dist/` 留一个 322MB 的 `.old-*`，四轮堆了 1.3GB。

7. **随机挑端口会撞上 Chromium 的「不安全端口」黑名单。** 第一版让系统自己挑（`listen(0)`），
   开发态第一次就抽到 **1723**（PPTP），页面直接 `ERR_UNSAFE_PORT` ——
   服务好好活着、日志一切正常，就是白屏。→ 改成自己从 18000-28999 里挑，
   并过一遍 Chromium 的名单（`net/base/port_util.cc`，含 1719/1720/1723/6666/10080 等）。

8. **冒烟截图会在产物目录里写下真实数据。** 截图那一步是以真实客户端跑起来的，
   它会在 exe 旁边建 `data/`：账号 puuid、昵称、战报、名录。而 zip 紧接着就打这个目录 ——
   第一版压出来的包里真的夹带了一份 `accounts.json`，跟「数据不进包」的红线直接冲突。
   → 压包前（以及不压包时）`setAside(data/)`。**产物是干净的，首次运行自己建。**

### 自检口径

打包脚本最后一步会**让客户端自己截一张图**（`preview/desktop-client.png`，窗口隐藏状态下
`capturePage`），这是「页面确实装在自己的窗口里」的唯一硬证据。取不到图时，它会把
`data/desktop.log` 的尾部直接打在报告里 —— 不用再去翻目录。

单实例行为用**日志启动段数**验证：起第二个实例后，`data/desktop.log` 里的
「===== … 启动 =====」段数必须不变（第二个实例自己退让，不去抢服务）。

### 顺带一提

- 客户端日志落在 `data/desktop.log`（打包后的 GUI 进程没有控制台，这是唯一排障口），
  超过 1.5MB 轮转一代。
- `backgroundThrottling: false` 是刻意关的：页面靠 SSE + 5 秒轮询盯客户端，
  窗口最小化时若被 Chromium 省电逻辑节流，「打完一局自动登记」就会迟到。
- 未做代码签名，首次运行 Windows 会拦一次（「更多信息 → 仍要运行」）。

## 十、标签失灵与安全升级（2026-10-10 深夜）

### 10.1 为什么「背锅侠 / 混子」从来不出现

大哥的原话：**「deepseek 结果中只有大腿和普通，从来没见过背锅侠和混子」**。
先量化，再下判断 —— 把 12 份历史战报的标签统计出来：

| 标签 | 出现次数 | 说明 |
|---|---|---|
| CARRY 大腿 | 25 | 模型很乐意夸人 |
| NORMAL 普通 | 88 | 默认落点 |
| BLAME 背锅侠 | 6 | 12 局里只有 6 局出现，且都是「刚好」跌破 40 |
| TEFLON 不粘锅 | 1 | 门槛 死亡 ≤4 且 伤害/分 ≥800 也不容易同时满足 |
| FREELOADER 混子 | 1 | 门槛是死亡 ≥18 **且** 参团率 ≤0.5 —— 近乎空集 |

真正的原因有三层，只修一层是没用的：

1. **模型给分挤在安全区。** 12 局里有 5 局最低分连 40 都没跌破（45/45/50/52/55/58），
   而 BLAME 的判定线就是「≤ 40」。不是模型不给，是它的分数压根没走到那条线。
2. **混子的门槛在大乱斗里几乎不可能同时成立。** 实测分布：死亡 12-22、参团率 0.51-0.87。
   要「死 ≥18 **且** 参团 ≤0.50」—— 死了 18 次的人多半打过不少团，参团率下不去。
   → 放宽到 **死亡 ≥15 且 参团率 ≤0.55**。
3. **「胜方免责」只挡了一半。** 原来只判「本局赢了 → 我方不得 BLAME」，
   漏了「本局输了 → 敌方不得 BLAME」。真机就出现过「我方战败，模型却给赢家崔斯特
   判了背锅侠」这种自相矛盾的结论。→ 改成双向：BLAME 只能挂在输的那一边。

### 10.2 三层修法（提示词 → 校验 → 代码兜底）

| 层 | 做了什么 | 为什么放在这一层 |
|---|---|---|
| 提示词 v3.1/v3.2 | ① 混子线放宽 ② 新增「分数带」绝对标准（90+ / 80-89 / 60-79 / 45-59 / ≤40 各代表什么）③ BLAME 写成败方问责标签 ④ 混子写成「客观门槛，不是裁量空间」⑤ 胜方免责改双向 | 判定标准属于模型该读的东西，先写清楚 |
| 结构化校验 | `validateResult` 的 80/40 改为从 `DEFAULT_PARAMS` 取（此前硬编码，界面一调参就会错杀）；胜方免责改双向 | 这是「标签 ↔ 分数 ↔ 阵营」的一致性，属于硬约束 |
| **标签校准（新）** | `reconcileLabels()`：客观门槛命中而模型没判 → 代码改判并钳分数；败方一个 BLAME 都没有 → 最低分者顶上（除非模型在 verdict 里明写「败因在团队而非个人」） | 阈值是参数层定的政策，模型有裁量空间就会漂移，必须由代码兑现 |

实测对照（同一局 `401107523855`，同一提示词只差版本）：

| 版本 | 标签分布 | 分数区间 | 备注 |
|---|---|---|---|
| v3.0（原） | 大腿×3 · 普通×7 | 58 – 86 | 一个负面标签都没有 |
| v3.2（新） | 大腿×2 · 普通×7 · **背锅侠×1** | 38 – 88 | 极差 38 → 48 |

其中就包括 19 死 / 参团 49% 的薇恩 —— 那一行现在会明说改判理由。

**代价与边界**：改判会往 `reason` 末尾追加一句「（按客观门槛改判混子：死亡 19 ≥ 15 且参团率 49% ≤ 55%）」，

### 10.5 打包产物要能升级，且不能丢数据

大哥的要求：**「打包文件要支持更新并且不能丢原始数据」**。

先说清楚数据在哪儿：客户端是便携目录，`data/`（战报 / 账号 / 名录 / 缓存）就在 exe 旁边，
代码在 `resources/app/`。所以「升级」的定义就是：**换 resources/app，一个字节都不碰 data/**。

```bash
npm run pack:update      # → dist/LOL背锅侠-升级包-vX.Y.Z.zip（约 0.3MB，29 个文件）
npm run pack:desktop     # 完整包，末尾会自动附带生成升级包
```

用法：把 zip 拖到安装目录里的 `update.bat` 上（或 `update.bat <zip>`）。

三道防线，缺一不可：

1. **打包侧**：升级包组装完立刻用**客户端同款 zip 读取器**扫一遍条目，
   发现任何 `data/` 就 `exit(1)` 并打印是哪几个文件。
   （不用 `tar -tf`：全角文件名会让 bsdtar 解错，实测踩到过。）
2. **安装侧**：`apply-update.mjs` 收到含 `data` 条目的包直接**拒绝安装** —— 那是打包错了，不是升级。
3. **流程侧**：升级器对 `data/` 唯一的写操作是往 `data/update.log` 追加一行；
   先备份旧代码到 `resources/app.bak-<时间戳>`，写入失败自动回滚，备份最多留 2 份。

真机验证（`dist/LOL背锅侠/`，先塞一个 `data/smoke-marker.txt` 当存量数据）：

```
版本      1.0.0  →  1.1.0
备份旧版本 resources\app.bak-1791649894296
已升级到  v1.1.0
数据保留  9 个数据文件仍在 data
```

升级后核对：`smoke-marker.txt` 原样还在、`data/` 9 个条目一个不少、`update.log` 记了两行、
`resources/app.bak-*` 可回滚、客户端能正常起来（截图 `preview/desktop-updated.png`）。
再升级一次：备份轮转为 2 份、数据仍然完好。

**四个坑**（都在这一轮踩到）：

1. **鸡生蛋**：老安装里既没有 `update.bat` 也没有升级器，拿什么升级？
   → 升级包根目录同时带上 `update.bat` 和 `update.bat` 会调用的 `apply-update.mjs`；
   老用户解压后双击，脚本发现旁边没有 exe 就知道自己是在「解压目录里跑」，
   问一句客户端目录（`--root`）即可 —— 一次性，升完就自带升级能力。
2. **Electron 就是 Node**：`ELECTRON_RUN_AS_NODE=1` 时它完全不加载 app，直接执行给定的 .mjs。
   于是目标机器**不需要装 Node**（实测 v24.21.0）。注意这个变量必须 `set` 上、别写成空串。
3. **`__dirname` 在 .mjs 里不存在**：升级器是 ESM，得走 `fileURLToPath(import.meta.url)`；
   而且它不会被 esbuild 转成 CJS（那条链路只服务 SEA 单文件版）。
4. **中文路径的老对手**：升级包文件名带「升级包」三个全角字，`bsdtar -tf` 直接打不开
   （报 `Failed to open archive`）。所以包内自查一律走 Node 自己的 zip 读取器。

## 十一、安全加固一轮（2026-10-11，v1.1.3）

按「本地小工具也可能被网页蹭」的思路过了一遍，改了八处。每一处都留了自检脚本，
因为这类问题**看代码看不出来**，只能发真请求验。

### 11.1 本地 API 的可信边界（P1）

原先 `sendJson` 一律带 `Access-Control-Allow-Origin: *` —— 用户开着服务时，
浏览器里**任意一个网页**都能跨域读走战绩 / 名录（含还原后的真实昵称），
还能 POST 改配置、关监视器、反复触发判定（那是真金白银）。没有 Host 校验，
还额外存在 DNS rebinding 路径。

三道闸，缺一不可（`server/server.mjs` 顶部注释写了为什么）：

| 闸 | 挡什么 |
|---|---|
| `Host` 必须是 `127.0.0.1` / `localhost` / `[::1]` | DNS rebinding |
| `Origin` 只回显白名单，不再返回 `*` | 普通跨域页面（拿不到 CORS 许可，浏览器自己拦） |
| `/api/*` 要会话令牌（每次启动随机） | 前两道被绕过时（如 `file://` 的 null origin） |

实现上三个坑：

1. **令牌怎么发**：随首屏 HTML 下发（`<meta name="bbx-token">`），跨域页面读不到同源 HTML，
   也就拿不到。静态资源**不**要令牌 —— 先有页面才拿得到令牌。
2. **改不了请求头的地方**：`<img src>` 与 `EventSource` 发不出自定义头，
   所以令牌额外接受查询串 `?token=`（`api.js` 里 asset / subscribe 两处）。
3. **`sendJson` 需要 `req`** 才能判断该不该回 CORS 头 —— 于是全量改成
   `sendJson(req, res, ...)`。别用「模块级变量记住当前请求」那种写法：
   请求之间有 await 交错，会串。

`readBody` 强制 `application/json`（含 `; charset=utf-8` 写法）否则 415 ——
堵的是「表单伪装成简单请求、不触发预检直接打写入口」那条 CSRF 通道。
配套：415 / 400 这类「请求不合规格」不能按 500 兜住，否则调用方分不清是自己写错了还是服务挂了。

自检：`npm run check:api`（起临时服务，扮演本机界面 / 恶意页面 / DNS rebinding 三种角色）。

### 11.2 Key 与 data/ 物理隔离（P2）

Key 原先明文写在 `data/config.json`，而 README 教的是「整个目录拷走即可运行」——
`data/` 又装着战报（其中 `data/reports/` 那份本来就是要能分享出去的），一个手滑就外泄。
（顺带说清：整个 `data/` 目录**不能**外发 —— 里面还有 `names.json` / `roster.json` / `searched/` 这些带真名的文件。
「目录可以整个拷走」说的是**迁移到自己的另一台机器**，不是发给别人。）

- Key 改落**用户配置目录**（Windows `%LOCALAPPDATA%\LOL背锅侠\config.json`，
  环境变量 `DEEPSEEK_API_KEY` 仍最高优先）。
- 启动时自动**搬家**：老配置里的 Key 搬到新位置，并从 `data/config.json` 里删掉那一字段
  （其余偏好原样留着）。幂等。
- 界面保存 Key 时明确提示「明文保存在 <路径>，请勿外发」—— 路径由服务端给，不让前端猜。
- 打包后 `tools/build-desktop.mjs` 会扫产物里有没有 `sk-…`（只扫文本形态：
  exe / dll / pak 里随机出现 `sk-` 字节是家常便饭，扫了全是假警报）。

### 11.3 只读详情也要过归属闸（P3）

`match-history` 端点**对任意 gameId 都返回数据**（可能是别人的对局），
`analyzeMatch` 早有 `NOT_MY_MATCH` 防线，只读详情那条路一直没有。
现在 `readMatchView` 补上同一道闸，三种合法情况放行：索引里已记归属 / 当前登录账号在局里 /
显式 perspective 且那人本机认识且确实在这一局。

★ 顺序很要命：**校验必须排在 `rememberPlayers` 之前** —— 名录一攒，
这一局的十个人就都变成「本机认识的人」，第三条判据立刻失效，等于没校验。

### 11.4 升级包：Zip Slip + 完整性（P4）

- 条目名先过 `safeSegments()`（拒绝绝对路径 / 盘符 / 反斜杠 / `..`），
  落地前再用 `resolveInside()` 确认拼出来的路径还在临时目录里 —— 名字和结果各查一遍。
- `update.json` 验 `version` 格式；`rootFiles` 只允许白名单（`update.bat`）。
- manifest 增加逐文件 sha256，装之前逐条对；包里出现清单外的文件也拒。
- Electron 运行时下载后会尝试对官方 `SHASUMS256.txt`（拿不到就明说没验，不假装验过）。

### 11.5 lockfile 探测别再全盘扫（P5）

监视器每 5 秒一次 `readConnection()`，同步把 24 个盘符 × 8 条候选路径扫一遍 ——
挂了休眠网络盘 / 空光驱的机器上，单个 stat 可能阻塞几秒，单线程的服务端和界面一起卡。

- 探测结果缓存 15 秒；**已连上时直接复用上次那条 lockfile 路径**，一次都不扫。
- 常驻循环改走 `readConnectionAsync()`（`fs.promises`，盘符并发上限 4）。

### 11.6 索引写覆盖（P6）

`matches.json` 是「读-改-写」，`listMatches` 中间要拉几百局 LCU 详情（跨 await），
这期间判定完成 / 监视器扫描也会写盘 —— 后写者拿旧快照写，就把人家刚加的条目抹了
（表现为「刚重判完，列表那行又变回旧结论」）。

修法：**写盘前重新读一次磁盘并合并**。函数体是同步的，Node 单线程，
「读 → 合并 → 写」这段不会被打断，不需要额外队列 —— 真正的坑从来是跨 await 的旧快照。
`names.json` 同病，一并修了（`saveNamesIndex`）。`roster.json` / `accounts.json`
是「读到写之间不跨 await」，本身就安全，没动。

### 11.7 换号窗口期别张冠李戴（P7）

`summarizeGame` 原先 `ownerPuuid: myPuuid || null` —— 换号后，客户端缓存里
上一个号的对局会被记到新号名下（那些局还没登记过，`mergeEntry` 保不住）。
改成 **本人确实在这一局里才算他打的**（`myPid != null`），否则留空归入 unowned。
`listMatches` / `sweepIntoIndex` 两处不再显式传 `ownerPuuid`，让这条默认逻辑生效。

### 11.8 小项（P8）

- CSP：页面加 meta，服务端对 HTML 响应也带一份。必须开 `'unsafe-inline'`
  —— 图标占位用的是内联 `onerror`，整页还有一堆内联 style。
- Electron 渲染进程 `sandbox: true`（无 preload、不需要 node，那就关进沙箱）。
- `setMatchesSum('读取失败：' + e.message)` 是唯一一处把外部字符串当 HTML 写的，补 `esc()`。
- `start.bat` / `check.bat` 里写死的开发机 node 路径 → 先 `where node`，再回退 `node`。
- **模型 id 真的有问题**：`deepseek-v4-flash` 不在 `/v1/models` 清单里，
  但实测能调用（是 `deepseek-flash` 的别名，返回体里 `model` 就是 `deepseek-flash`）。
  所以 `deepseek-check.mjs` 不能只看清单 —— 清单里没有时再发一个最小请求实测，
  否则会误导人白改一遍模型 id。已跑一次真实判定确认 `meta.source === 'deepseek'`。

## 十二、判定过程可见（2026-10-11，v1.2.0）

需求原话：**「在 deepseek 思考过程中加入思考中的状态展示，最好能显示出来过程，
会出现时间太久了本地模型兜底的情况」**。

### 12.1 原来为什么看不见

`callDeepSeek` 是**整包等到底**：`await res.text()` 一把拿完，中间一个字节都不往外说。
判定十几秒起步，界面只能干转那四步假动画 —— 用户分不清「模型在写」和「已经卡死」，
最后跳出来的结论是模型写的还是本地兜底的，也只能靠 toast 里那半句话猜。

### 12.2 改成流式

`body` 加 `stream: true` + `stream_options: {include_usage: true}`，读 `res.body.getReader()`，
按 SSE 行解析 `delta.content` 累加。每来一段就 `armIdle()` 续命、按 250ms 节流回调 `onProgress`。

- **兼容性分支**：`content-type` 不是 `event-stream`（网关不认 stream 参数）时退回整包解析，
  只是界面拿不到「输出中」这一档（只有 wait → parse）。
- **usage 在最后一个 chunk**：那帧 `choices` 是空的，只有 `usage`，所以判断要用 `js.usage` 而不是
  只看 `choices[0]`。

### 12.3 超时语义改了（这一条比显示更重要）

原来 `timeoutMs: 60_000` 是**整包上限**。报告变长之后（v3.0 起 insight 300-400 字、
teamInsight 三条），60s 经常不够 → 掐断 → JSON 截断 → 兜底。
**「判定老走兜底」的主因就是这个**，不是模型不行。

现在三段：

| 计时器 | 默认 | 管什么 |
|---|---|---|
| `firstByteMs` | 30s | 等首字节 —— 排队 / 网络不通属于这一类，等太久没意义 |
| `timeoutMs` | 60s | **语义变成「两次数据之间的静默上限」**：模型一直在写就不打断 |
| `maxMs` | 150s | 总时长硬顶，免得一个卡住的流把界面挂死 |

谁先响就记下**中文理由**（`stopReason`），一路带到兜底的 `errors[0]` 与界面提示里 ——
「模型输出中断超过 60 秒」这种话用户才看得懂。

### 12.4 阶段与界面

阶段字面量在 `src/deepseek/judge.mjs` 的 `JUDGE_PHASES`：
`prepare → submit → wait → stream → parse → done / fallback`。
服务端 `judgeProgress()` 转成 SSE 的 `{type:'judging'}`，界面 `onJudgeProgress()` 接管假动画：

- 阶段 → 四步动画的第几步（`PHASE_STEP`）；真进度一到就 `stopFakeSteps()`，
  **两边抢着改同一批 `.step` 会让步骤来回跳**。
- 状态行 `#judgeStatus`：`模型思考中 / 模型输出中 · 已输出 1.2k 字 / 校验输出 / 已改用本地兜底判定`。
- 两次事件之间自己走秒：记 `judgingAt`，`elapsed = ev.elapsedMs + (now - judgingAt)`，200ms 一跳。
- **兜底整行变警示色**，并在 meta 里写原因 —— 用户要能看出「这次结论不是模型写的、为什么」。

### 12.5 踩到的两个坑

1. **秒表泄漏**：`done / fallback` 时我只 `return` 没 `stopJudgeTick()`。
   浏览器里是白刷 DOM，**无头自检里是进程不退出** —— ui-smoke 直接挂到超时被 kill 才暴露出来。
   现在收尾阶段一律先停表。
2. **ui-smoke 订阅不到**：桩里 `subscribe: () => null`，把界面给的回调丢了。

## 十三、YY 语音播报方案调研（2026-10-11）

需求：「怎么用语音在 YY 播报」。这一节只做**调研与可行性实证**，不改产品代码。
PoC 落在 `_ref/tts/`（该目录已在 `.gitignore` 里，不入库）。

### 13.1 现状：稿子有了，声音出不去

`buildCast()` 已经能按语气档位拼出可读的播报稿，但「输出通道」那块面板是**写死的示意图**
（`web/app.js` 的 `renderCast()` 里 `['合成','Edge TTS']` 那几行），TTS 与声卡路由一行实现都没有。

### 13.2 YY 侧的三条硬事实（决定了路只能这么走）

- **YY 只认「麦克风输入设备」**，没有公开的频道推流 API / 机器人插件接口。
  所以声音必须以「麦克风」的形态进 YY → **虚拟声卡是必需品，不是可选项**。
- 设置里有三个坑，漏一个就「听不见」：
  1. 设置 → 音频设置 → 麦克风 → 选虚拟声卡的**输入端**（`CABLE Output` / `麦克风 (ToDesk Virtual Audio)`）；
  2. **通话模式必须是「自由说话」** —— 默认是按键说话（F2），而合规边界里写了不模拟键鼠，
     我们按不了键，声音就传不出去。**这条最容易被忽略**；
  3. 调音台的「麦克风增强 / 降噪 / 自动增益」建议关掉：虚拟声卡进来的是干净线路信号，
     被当成噪声压掉就哑了。

### 13.3 虚拟声卡四条路线

| 路线 | 要装东西 | 能不能同时自己说话 | 说明 |
|---|---|---|---|
| **A 用现成的 ToDesk Virtual Audio** | 不装 | 不能 | **本机已实测环回通过**；但它是远控软件带的，随 ToDesk 卸载消失，且被系统当成默认通信设备 |
| **B VB-CABLE（推荐）** | 免费驱动 | 不能 | `CABLE Input` 当播放器输出、`CABLE Output` 当 YY 麦克风。最标准、资料最多 |
| C Voicemeeter Banana | 免费 | **能**（物理麦 + TTS 混一路） | 多一层驱动，学习成本高；真需要「边说边播」时再上 |
| D 立体声混音 Stereo Mix | 不装 | 能，但会把游戏声音一起混进去 | 不是所有声卡都提供这个端点 |

### 13.3.1 「用自己的麦播报、不想来回切输入设备」

**先澄清一个物理事实：麦克风是输入设备，声音「播」不进去。**
所以「用我的麦播报」在操作上只有两种可能：

1. **让 TTS 走 YY 混音**（YY 自己把系统声音混进麦克风）；
2. **把麦克风和 TTS 混进同一条虚拟线**，YY 的麦克风**常驻**这条线 —— 从此不用再切。

| 路线 | 做法 | YY 输入设备 | 代价 / 风险 |
|---|---|---|---|
| ① YY 自带「卡拉OK混音 / 内放」 | TTS 播到默认耳机，调音台 → 高级 → 勾「使用软件卡拉OK混音」 | **物理麦，永远不动** | 依赖 YY 版本还留着这功能；老版本是「选播放器」式捕获，不一定抓得到我们这个应用；游戏声音会一起混进去 |
| ② **虚拟声卡 + Windows「侦听此设备」（推荐）** | 麦克风属性 → 侦听 → 勾「侦听此设备」→ 播到 `CABLE Input`；TTS 也 `setSinkId` 到 `CABLE Input` | **`CABLE Output`，常驻不动** | 装一次驱动；说话有几十毫秒系统延迟；**YY 里的降噪 / AGC 必须关**，否则会跟混音打架 |
| ③ Voicemeeter Banana | 物理麦 + 应用音源在调音台里混一路 | `Voicemeeter Output`，常驻不动 | 功能最强（两路音量独立可调），学习成本高 |
| ✗ 音箱外放让麦拾音 | TTS 从音箱放出来，物理麦收进去 | 物理麦，不动 | 音质差、房间混响、游戏声音全混进去、可能啸叫。**别这么干** |

路线 ② 的三步（装好 VB-CABLE 后只做一次）：

1. `mmsys.cpl` → 录制 → 双击你的麦克风 → 「侦听」→ 勾「侦听此设备」→ 通过此设备播放选 `CABLE Input`；
2. 应用里把播报输出设备选成 `CABLE Input`（TTS 走 `setSinkId` 直达，不占你的耳机）；
3. YY → 音频设置 → 麦克风 → 选 `CABLE Output`（**之后永远不用动**）。

结果：你说话和 TTS 播报**同时**进 YY，输入设备再也不用切。

**三个必须注意的副作用**：

- 侦听是系统级转发，**你自己的声音会晚几十毫秒到 YY**（队友无感，你自己别开 YY 的「麦克风监听」，否则会听到延迟的自己）；
- **YY 的降噪 / 自动增益一定要关**：它们会把混进来的线路信号当噪声压掉，表现为播报开头被吃掉几个字；
- 侦听开着时麦克风一直被系统占用，个别机器会有轻微底噪 —— 嫌吵就把侦听关掉，回到「播报时切一次设备」的原始方案。

### 13.4 TTS：零依赖直连 Edge TTS —— 已跑通

`_ref/tts/edge-tts-poc.mjs`，只用 `node:crypto` + Node 22 内置的 `WebSocket`：

- 端点：`wss://speech.platform.bing.com/consumer/speech/synthesize/readaloud/edge/v1`；
- 令牌 `Sec-MS-GEC` = `SHA256(Windows 文件时间按 300 秒对齐 + 固定串)` 大写十六进制；
  固定串 `6A5AA1D4EAFF4E9FB37E23D68491D6F4`，`WIN_EPOCH = 11644473600`；
- 两条消息：`Path:speech.config`（声明 outputFormat）→ `Path:ssml`（正文）；
- 音频帧是二进制，前 2 字节是 header 长度，跳过即可；`Path:turn.end` 收尾
  （**服务端不会主动关连接**，客户端要自己收）。

实测（本机）：

| 文本 | 首字延迟 | 总耗时 | 产物 |
|---|---|---|---|
| 短句 22 字 | 958ms | 1.7s | 62KB MP3 |
| 长句 60 字 | 2.07s | 2.4s | 103KB MP3 |

音色实测可用：`zh-CN-XiaoxiaoNeural`（晓晓）、`zh-CN-YunxiNeural`（云希）、
`zh-CN-YunyangNeural`（云扬，播音腔）、`zh-CN-liaoning-XiaobeiNeural`（东北小北，适合毒舌档）、
`zh-CN-XiaoyiNeural`（晓伊）。

**四个坑（都是真踩的）**：

1. **SSML 的 xmlns 必须小写 `synthesis`** —— 写成 `Synthesis` 服务端直接断连，
   close code 1007 的 reason 就是一句明确的提示（`Please provide default namespace …`）。
   **这个 reason 很有用，调试时一定要打出来。**
2. **`ws.binaryType = 'arraybuffer'` 必须在 open 之后设** —— undici 默认是 `'blob'`，
   `Buffer.from(Blob)` 得到空 buffer，表现为「连上了、turn.start 也来了，但一个字节音频都没有」。
3. **偶发 non-101 / ByteParser 报错** —— 十几秒内连着请求会被掐。生产实现必须带
   **重试 + 退避**，不能一次失败就判「服务不可用」。
4. Node 的 undici WebSocket **允许自定义 `Origin` / `User-Agent`**（这两个在浏览器里是禁改头），
   所以伪装成 Edge 扩展这一步不需要手写 WebSocket 客户端。

### 13.5 播放：Electron `setSinkId` —— 已跑通

`_ref/tts/audio-probe/main.cjs` 实测：

- Electron/Chromium **能枚举音频输出设备**且**带完整标签**（不需要申请权限）；
- `HTMLMediaElement.prototype.setSinkId` 存在，实测调用成功切到指定设备；
- **坑：`data:` URL 不是安全上下文**，`navigator.mediaDevices` 直接不存在 →
  必须用 `file://` 或 `http://127.0.0.1`，而这正好是本项目两种形态的加载方式。

### 13.6 环回实证：虚拟声卡真的通

`_ref/tts/audio-probe/loop.cjs` 做的事：把 MP3 播到「扬声器 (ToDesk Virtual Audio)」，
同时从「麦克风 (ToDesk Virtual Audio)」用 `getUserMedia` 录回来量 RMS。

结果：**peak 0.489 / RMS 0.459 / 94 个采样 —— 通路**。
（getUserMedia 时要关掉 `echoCancellation` / `noiseSuppression` / `autoGainControl`，
否则浏览器会先把信号处理一遍；Electron 里还要 `setPermissionRequestHandler` 放行 `media`。）

### 13.7 离线降级：SAPI → WAV —— 已跑通

`_ref/tts/audio-probe/sapi.cjs`：主进程 spawn 系统 PowerShell 调 `System.Speech`。

- 本机可用中文声音：**`Microsoft Huihui Desktop | zh-CN`**（`System.Speech` 看得见 Desktop 版；
  `Speech_OneCore` 里那几个 Huihui / Yaoyao / Kangkang / Hongyu 对它默认不可见）；
- 合成出 115KB WAV。**WAV 走的是同一个 `<audio>` + `setSinkId` 播放器，所以同样能进虚拟声卡**；
- **Web Speech API 这条路堵死**：Electron 里 `speechSynthesis.getVoices()` 是空的（count=0），
  而且它**没法指定输出设备**，播不到虚拟声卡。别往这边试。

### 13.8 真要落地时改哪几处

## 十四、升级器「一闪而过」事故（2026-10-11，v1.2.1）

现象：把 `LOL背锅侠-升级包-v1.2.0.zip` 拖到安装目录的 `update.bat` 上，
CMD 窗口一闪而过，版本号没变。**三个 bug 叠在一起**，必须全修才见效。

### 14.1 头号元凶：bat 里的字面括号把整个批处理作废了

`update.bat` 里有一段：

```bat
if "!APP_EXE!"=="" (
  ...
  set /p INSTALL=Paste the client folder to upgrade (the one with LOL exe): 
  ...
)
```

提示语里的 `(the one with LOL exe)` 是**字面量**，但它坐在 `if (...)` 块里 ——
那个 `)` 把块提前闭合，剩下的 `:` 就成了非法命令。cmd 在**解析阶段**直接把整个
批处理作废：一行输出都没有、退出码 **255**，窗口自然一闪而过。

- 报错原文：`此时不应有 :。`（英文系统 `was unexpected at this time.`）
- **条件为假时也一样炸** —— cmd 要找块的结尾，就得先把块读完。实测过。
- 修：别用括号块，改 `if not ... goto :label`，让 `set /p` 待在顶层。
- 顺手把 `set /p` 改成 `set /p "VAR=prompt"` 形式，并在提示前 `set INSTALL=` 清空
  （`set /p` 遇到空输入会**保留旧值**，不清空就会拿上一个值往下走）。

### 14.2 二号元凶：update.bat 从来没进过 sha256 清单

`buildUpdateZip()` 里 `hashWalk(stage)` 跑在**复制 update.bat 之前**，
于是包里有 `update.bat`，清单里却没有。升级器按 P4 的规则「清单外的条目一律拒装」，
直接回一句 `update.bat 不在 update.json 的文件清单里 —— 拒绝安装`。

修：把 `update.bat` 的复制提到算清单之前。加注释说明顺序为什么不能反。

> 这条最阴险 —— 打包脚本全程绿，只有用户真装一次才会炸。

### 14.3 三号元凶（自检本身的）：假绿断言

第一版自检在**仓库根目录**跑 `update.bat`。根目录里既没有 exe 也没有
`resources/app/desktop/apply-update.mjs`，脚本早在「找不到升级器」那条分支就
`exit /b 1` 了，**根本走不到出问题的那段** —— 断言永远绿。

改成：造一个**沙盘安装目录**（`.tmp/check-update-pack/`：有假 exe、有
`resources/app/`、有 `update.bat`、版本号故意压成 `0.0.0-sandbox`），
再传一个**真实存在**的升级包路径，脚本才会一路走到后面那些 if 块。

### 14.4 新增自检 `tools/check-update-pack.mjs`

三段，每段都验过「会因回归而红」：

| 段 | 验什么 | 注入 bug 后的表现 |
|---|---|---|
| bat 解析 | 沙盘目录里跑 update.bat，抓 `此时不应有` / `is not recognized`，并断言**有输出且不是 255** | `✗ 此时不应有 :。` + `exit=255` |
| 升级包清单 | 每个条目都在 `files` 里、哈希对得上、`rootFiles` 在白名单且真的在包里、0 个 data 条目 | `✗ 缺 update.bat` |
| 端到端 | 沙盘里真装一遍：退出码 0、版本升到清单版本、`data/` 一个字节没动、留了 `app.bak-*`、update.bat 被覆盖 | `✗ 升级器退出码 0` |

两个实现坑：
- **cmd 的输出是 GBK**，得先 `TextDecoder('gbk')` 再匹配关键字（本文件是 UTF-8）。
- **`pause` 是从控制台读键的**，管道喂回车没用，进程会一直挂着。
  把 stdin 设成 `'ignore'`（= NUL）它就立刻返回。
  另外 `spawnSync` 在本机会偶发 `EBUSY`，改用异步 `spawn`。

### 14.5 复现与实证

- 复现旧包：在真实安装目录下跑 update.bat → exit 255、零输出、`此时不应有 :。`
- 修完在**真实安装目录** `D:\Program Files (x86)\LOL背锅侠` 上跑通：
  `1.1.3 → 1.2.1`，9 个数据文件原样保留，回滚点 `resources\app.bak-<ts>` 已生成，
  `data/update.log` 记了两条。

> 顺带确认：`D:` 上的 `Program Files (x86)` 写入没被 UAC 拦（实测可写），
> 所以不需要给 update.bat 加自动提权。若哪天遇到 `EPERM`，
> 提示用户右键「以管理员身份运行」即可，别自作主张改目录权限。

### 14.6 提醒用户

**升级完要重启客户端** —— 界面上的版本号来自正在运行的进程，
文件换了但进程没重启，版本号还是旧的。

## 十五、查某人战绩：能拿到他自己的对局了（2026-10-11，v1.2.2）

需求：「搜索只能搜到与我相关的对局，可以直接拉到搜索用户所有的对局吗」。

答案是**能，而且以前的代码注释写错了**。

### 15.1 一条被实测推翻的旧结论

`server/roster.mjs` 顶部原话：「matchlist 对**任意 puuid** 都返回本机缓存的那几局
（实测拿四个不同的 puuid 去问，回来的 gameId 一模一样），等于忽略入参。」

**实测不成立**。`/lol-match-history/v1/products/lol/{puuid}/matches` 对任意已知 puuid
是**按人返回**的：

| 目标 | accountId | 返回局数 |
|---|---|---|
| 自己 | 17005381865 | 21～200 |
| 名录 #1 | 16849795873 | 11～21 |
| 名录 #2 | 15782322027 | 21 |
| 名录 #3 | 17119736296 | 21 |

accountId 各不相同、gameId 集合也各不相同。当初那个结论多半是**参数没带对**（见下）。

### 15.2 三个实测出来的上限（别再踩）

1. **`endIndex` 超过 50 反而变少** —— 50 给 51 局，100 / 300 只回 11～21 局。
   所以固定用 50。这是最反直觉的一条。
2. **`begIndex` 翻页无效** —— 0 / 20 / 40 / 100 / 190 返回同一批；
   换参数名（`startIndex` / `count`）直接 400。没有第二页，别做分页。
3. **条数不稳定**（同一人不同时刻 11 / 21 / 51），取决于客户端本地缓存。
   只能「有多少拿多少」，界面别承诺固定条数。

另外：**列表元素只含被查的那 1 个人**（`participants.length === 1`），
要判定必须再逐局拉 `/lol-match-history/v1/games/{gameId}`（那里才是 10 人 + teams）。
所以这个端点只用来**扩充清单**，不能拿来直接出结论。

### 15.3 改了什么

- `src/lcu/client.mjs` 新增 `readMatchListFor(conn, puuid)`，注释把上面三条上限写死。
- `server/service.mjs` 的 `summonerMatches()`：清单改成**名录 ∪ 客户端战绩**，
  并拆出 `scannedFromRoster` / `scannedFromClient` 两个计数给界面说明来源。
- `server/roster.mjs` 顶部注释订正（旧结论会持续误导人）。

实测：查「路人甲」（名录里只见过 1 局）→ **51 局，其中 50 局来自客户端**，
全部能读到完整 10 人详情，视角正确（myTeamId=100 / WIN）。

### 15.4 顺带补的：陌生局「能看不能判」

拉到别人的局之后，点「开始分析」会被 `NOT_MY_MATCH` 挡住 ——
判定会写战报并把这一局 `rememberGame` 进「我的战绩」，那是别人的局，不能进我的库。

原先用 toast 报错，体验是「点了才知道不行」。改成入口就说清楚：

- `readMatchView` 返回新增 `owned`（`!!(owner || meInGame)`）；
- 界面 `renderAnalyzeBar()`：`owned === false` 时提示
  「这是别人对局里的原始数据 —— 可以看，但不判定」，按钮置灰成「不判定」；
- 状态点新增 `.ab-dot.off`（灰）—— 与「未判定」的黄区分开，两件事别混；
- 战绩汇总行补一句「其中 N 局来自客户端战绩（你不在场）」。

> 注意：`/api/match-detail` 在这局**已判定**时走的是战报分支（`{ok, hasReport, report}`），
> 不带 `dataset` / `owned`。所以 `applyReport()` 里要把 `detailOwned` 重置回 true，
> 否则从别人的局退回自己判过的局，按钮会一直灰着。

### 15.5 自检

`check-index-guard.mjs` 新增四条：

- 查询响应带两个来源的计数
- 并集不丢名录里的局（`scanned >= scannedFromRoster`）
- 详情返回带 `owned` 标志 ← **这一条单独验过会因回归而红**（把 `owned` 摘掉 → ✗）
- 分情况断言取值（false = 能看不能判 / true = 可判定）

> 教训：第一版写成 `if (owned === false) ok(...) else ok(...)`，
> **字段丢了也照样绿**。先断言字段在、再分情况断言取值，才守得住。

实测输出：`名录 1 / 客户端 50 / 合计 51`、`owned=false`。

## 十六、判定完成后卡在进度页（v1.2.3）

现象（1.2.1 真机）：点「开始分析」，进度页停在「校验输出」，下方状态行写着
**判定完成**，但页面不往下走，而且那一页**连返回 / 刷新都没有**。

### 16.1 根因：`await anim` 永久挂起（前端死锁，不是服务端）

`animateSteps()` 返回一个 Promise，`resolve` 藏在**最后一步的定时器回调里**。
v1.2.0 加了真进度之后，`onJudgeProgress` 收到任何 judging 事件就会调
`stopFakeSteps()` —— 它 `clearTimeout` 掉**整个 `fakeStepTimers` 数组**，
于是连最后一步那个「带 resolve 的定时器」一起被清掉。

时序（真判定十几秒，必然命中）：

```
t=0      点开始分析 → animateSteps() 挂起 4 个定时器（最后一个带 resolve）
t=~0.3s  SSE 推 stream → stopFakeSteps() → 定时器全清 → resolve 永远不会被调用
t=10.3s  SSE 推 done → 状态行显示「判定完成」
          …而 await anim 一直挂着，applyReport / show('report') 永远不执行
```

- 服务端**完全正常**：实测 `/api/analyze-match` 10.37 秒返回 200，
  SSE `done` 在 10303ms 推（比响应早 67ms），时序完全正确。
- 「正在生成战报」页本来就没有任何出口，所以一旦卡住就是死胡同。

### 16.2 修法（三层）

1. **收尾定时器绕开 `later()`** —— 独立排队，不依赖任何会被清掉的回调。
   假动画被掐断时照样 `resolve`，只是不再改 DOM（`fakeStepsHandedOver` 拦着）。
2. **`capWait(anim, 6000)`** —— 给「等动画」加硬上限。
   动画只是观感，却挡在「取到结果 → 切战报页」这条主链路上，
   宁可多演 0.1 秒也不能让它有机会困住用户。
3. **失败也必须离开进度页** —— 原来只有 `NOT_MY_MATCH` / `MATCH_DETAIL_EMPTY`
   两种 code 会 `show('report')`，其余错误弹个 toast 就留在原地；
   `applyReport()` 抛错更是直接变成未捕获异常。现在一律先切走再报错。

### 16.3 修的过程里踩到自己写的第一个补丁

第一版只把收尾的 `setTimeout` 移出 `fakeStepTimers`，
但它**仍然写在「最后一步」的 `later()` 回调内部** ——
那个回调被 `stopFakeSteps()` 清掉，收尾压根没被创建过，一样死锁。

是新增的那条冒烟断言把它抓出来的（第一次跑就是红的）。

> 教训：把「不能被取消的收尾」挂在「可被取消的定时器」里面，等于没摘干净。

### 16.4 回归保护

`ui-smoke.mjs` 新增「不卡进度页」：点开始分析 → 150ms 后投喂 `stream`
（模拟真进度抢戏）→ 等 2.4 秒越过动画收尾窗口 → 断言已离开进度页。
**这条断言在修复前是红的**，不是摆设。

## 十八、评分全面交给 DeepSeek：0-10 分 + 多因素综合（v1.2.5，提示词 v3.2）

需求原话：「你自己不要做评分模型了，把评分权限交给 deepseek，让 deepseek 返回分数
0-10 区间，并结合海克斯大乱斗的特性、装备、海克斯、阵容、阵亡时间、英雄特性
结合输出/承伤/治疗量等因素、参团等各种因素给出结论」。

### 18.1 分数制：100 → 10

| 参数 | 旧 | 新 |
|---|---|---|
| `carry_score_min`（大腿下限） | 80 | **8** |
| `blame_score_max`（背锅侠上限） | 40 | **4** |
| `blame_score_min`（崩盘线，新增） | — | **3** |
| 分数带 | 90+ / 80-89 / 60-79 / 45-59 / ≤40 | 9.5-10 / 8-9.4 / 6-7.9 / 4.5-5.9 / 3-4.4 / 0-3 |
| 梯度要求 | 极差 30+ | **极差 3+** |

**允许一位小数**（8.5）—— 10 档整数太粗，十个人挤在 11 个格子里分不出梯度。
`validateResult` 从 `Number.isInteger(0..100)` 改成 `0..10 的有限数`。

### 18.2 提示词新增「必须纳入判断的四类局内条件」

原来【评分维度】只讲了 PART/SURV/CONTRIB/RISK 四个方向，
承伤·治疗只在一个从句里带过。现在单独成段：

1. **英雄特性** —— 同一个 3/5/12，法师是经济没起来、坦克是替队友挡刀；
   用 `championType` 定「他该有什么表现」，**用错尺子量人就是误判**；
2. **装备（items）** —— 「经济落后没钱买」与「有钱但买错」性质完全不同，后者才是可控失误；
3. **海克斯（augments）** —— 随机分配，**只作背景、不构成个人责任**，
   但影响「这个英雄本局该打出什么」；
4. **阵容与团队处境** —— 个人崩了而团队本就崩，与团队崩了个人没崩，要分得清。

同时把 CONTRIB 拆细：坦克的高承伤 / 辅助的高治疗护盾 / 控制时长 / 分均，
都按**正面贡献**算，不要因为伤害数字低就判低分。

### 18.3 新增数据字段：player.deathTimes

「阵亡时间」原先只散落在两百多条时间轴事件里，模型要自己从
「谁在 03:12 死了」里挑出某个人的全部死亡时刻 —— 既费 token 又容易看漏。
`normalize.mjs` 现在按 pid 聚合出 `deathTimes: ["03:22","05:06",…]`。

- `timeDead` = 死亡**总时长**（合计、折算每分钟）
- `deathTimes` = 死亡**发生在什么时候**

**不违反四不原则**：这只是搬运既有事实，没有均值、没有排名、没有关联窗口。
【模式常识】也补了第 10 条：大乱斗死亡代价更重（不能回城补给），
所以「什么时候死」比「死了几次」更能说明问题。

### 18.4 踩到并修掉的一个真问题：轻微越界被当成输出质量不合格

改完第一次真机判定就翻车了：

```
source=fallback  errors=["p5 标 BLAME 但分数 4.2 > 4"]
```

模型给「BLAME 但 4.2 分」，线是 ≤4，**只差 0.2** —— 结果被 `validateResult` 判失败、
**白烧一次调用**、用户看到的还是兜底结论。100 制的档位更稀（80/40），
这种擦边概率低；**0-10 制的档位更密，擦边变成常态**。

改法两层：
1. `validateResult` 的自洽检查加 `SLACK = 1` —— 偏离超过 1 分才算输出不合格，
   小的放行；
2. `reconcileLabels` 新增 **⓪ 标签↔分数自洽钳位**：以标签为准把分数拽回线上
   （`labelLine()` 从 params 取阈值，不写死 8/4，否则界面调参就错钳），
   改动写进 reason 与 `_overrides`。

> 原则：**标签是模型深思熟虑的结论，分数只是刻度 —— 宁可动刻度也不动结论。**

修完再真机验：source=deepseek，1 处校准（p5 4.2→4），其余原样。

### 18.5 老战报兼容（12 份 0-100 制）

`tryLoadReport` 与 `listReports` 读出来后走 `migrateLegacyScores()`：
`score > 10` 即判旧制，折成十分位（92 → 9.2）。

**只改读出来的副本，不回写文件** —— 老战报的分数是历史记录，
偷偷改盘会让「同一局两次读出不同分数」。只有重新判定才会写成新制。

### 18.6 界面

- 分数显示加 `fmtScore()`（整数就显示整数，一位小数显示一位，不露浮点尾巴）；
- 分数条宽度 `--w` 乘 10（0-10 分 → 百分比）；
- `prototype/output/judge-report.json`（离线演示源）分数与文案一并迁移，
  并补上 `deathTimes`（从它自己的时间轴聚合）。
- `check-prompt-sync` 的参数个数**改成动态计算** —— 原来写死「14 参数」，
  加一个 `DEFAULT_PARAMS` 条目它就不报了，是个静默漂移点。

## 十九、播报稿去重：从「一句模板」到「句式池 + 本局事实」（v1.2.6）

大哥：「播报的内容重复性太高了，比如 401141622010 这把**全都是**全程隐身，伤害呢这种话，
优化下」。反过来看这句抱怨本身就很说明问题——**401141622010 那局根本没有混子**，
三个 CARRY 的旧模板都是「这局是爹，没他早没了」，所以是同一句念三遍。

### 19.1 根因：每个标签只有一句话

```js
carry: (n, c) => `${n} 的${c}这局是爹，没他早没了。`,   // 三个 CARRY → 三遍一模一样
freeloader: (n, c) => `${n} 的${c}全程隐身，伤害呢？`,
```

两个问题叠在一起：
1. **没有句式池** —— 同一标签的第 2、3 个人只能重复第 1 句；
2. **句子里没有任何本局数据** —— 念出来谁都一样，像复读机，
   「隐身」「送快递」都是标签的同义词，不是这个人干的事。

### 19.2 改法两条

**① 句式池 + 按标签内出场序号轮换**
`CAST_LINES[tone][label]` 每档语气每个标签 3–4 句，`buildCast` 维护一个 `used` 集合，
撞上已念过的就往后挪一句。同一局里不会出现两句一样的。

**② 每句填进这个人本局真正突出的那一件事**
新增 `castFacts(pid)`（客观数据 + 全场相对排名）与 `castHighlight(f, label)`（挑高光）：

| 高光 | 触发条件 |
|---|---|
| 输出全场第一 / 垫底 | `perMinute.damageDealt` 排名 |
| 全场击杀最多 | 击杀数第一且 ≥6 |
| 治疗全场第一 / 控制时长全场第一 | SUPPORT 与开团位的高光 |
| 全场死得最多 | 死亡数第一且 ≥8 |
| 扛伤最多，人却没了 | 承伤第一但死得多（**BLAME 专用**：把「扛伤」翻成讽刺） |
| 最后一次阵亡在 mm:ss | 有 `deathTimes` 时的收尾，承 v1.2.5 新加的字段 |
| 参团不到四成 | FREELOADER 专用 |

没有高光就退回 KDA（「24 杀 21 死 42 助攻」），**宁可朴素也别空着**。

> ⚠️ 这里的「全场排名」只用于**给人听的播报稿**，不喂模型 ——
> 四不原则约束的是送进 dataset 的那份数据，两者别混。

### 19.3 顺带修的两个真问题

1. **句间粘连**：`lines.join('')` 让 verdict 和第一句黏成
   「…无力回天路人辛的卡尔萨斯是本局胜负手」，读都读不顺。改 `join('\n')`，
   并给 verdict 补句号；顺带让 TTS 在句间自然停顿。
2. **句子太长**：TTS 是念的，一口气报三串数字听不进去。事实最多取 2 条、
   用「：」「——」断句，并把「这几波代价不小，{d}，节奏就是这么丢的」
   改成「这几波代价不小：{d}。节奏就是这么丢的」。

### 20.2 判定开放给别人的局

`analyzeMatch` 的 `NOT_MY_MATCH` 闸删掉了。ownerPuuid 现在**允许为 null**，
它只决定「判完算不算进「我的战绩」」：

| 情况 | ownerPuuid | 战报落盘 | 写 matches.json |
|---|---|---|---|
| 我在这局里 / 索引已登记 | 有 | ✅ | ✅ |
| 查别人的局 | **null** | ✅（按 gameId） | ❌ |

「按对局 ID 缓存」本来就是既成事实（`data/reports/<gameId>.json`），
所以这条需求不需要新机制，只是**把闸拆了**。

⚠️ **视角必须一起解决，否则判定没法看**：
判别人的局时我不在场 → `normalize` 认不出我方 → 10 人全落敌方。

`analyzeMatch` → `analyzeFromEog`，在 `myTeamId` 解析链里**排第一位**
（比 owner 更优先 —— owner 可能是「我」，而我想看的是被查那个人）。

> 踩坑：删掉 `if (!ownerPuuid) throw` 之后，下面那行「按原主人重判」的日志
> 还在 `ownerPuuid.slice(0, 8)` → null 上 slice，第一次真机判定直接
